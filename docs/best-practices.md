# 最佳实践 - 多 Agent 协作系统

## 1. 系统设计原则

### 1.1 明确分工
- **每个 Agent 职责单一**：不要试图让一个 Agent 做所有事情
- **职责边界清晰**：Writer 创作，Aligner 审核，Recorder 记录
- **避免职责重叠**：明确每个 Agent 的输入和输出

### 1.2 文档驱动
- **所有决策持久化**：不要依赖对话记忆
- **阶段性产出**：每个阶段都有明确的文档输出
- **可追溯性**：所有修改都有记录

### 1.3 质量门禁
- **必须审核通过**：不通过不能进入下一阶段
- **迭代有限制**：设置最大迭代次数，避免无限循环
- **人工兜底**：超过迭代次数必须人工介入

## 2. Agent 协作模式

### 2.1 主从模式
```
主 Agent (导演)
  │
  ├─→ Writer Agent (创作)
  │     └─→ 提交审核
  │
  ├─→ Aligner Agent (审核)
  │     └─→ 返回 PASS/FAIL
  │
  └─→ Recorder Agent (记录)
        └─→ 更新进度
```

### 2.2 信息传递
- **通过文档**：Agent 之间通过读写文档传递信息
- **通过 context**：委派任务时传递必要的上下文
- **避免直接调用**：Agent 之间不直接调用，通过主 Agent 协调

### 2.3 错误处理
- **迭代限制**：设置最大迭代次数（建议 5 次）
- **人工介入**：超过限制后人工审核和修改
- **记录失败**：Recorder 记录所有失败和修改历史

## 3. 成本控制策略

### 3.1 迭代优化
```python
max_iterations = 5  # 最大迭代次数

while iteration < max_iterations:
    script = writer.create()
    result = aligner.review(script)
    
    if result.passed:
        recorder.log_success()
        break
    else:
        iteration += 1
        writer.modify(result.feedback)

if iteration >= max_iterations:
    # 需要人工介入
    request_human_intervention()
```

### 3.2 上下文优化
- **精简 context**：只传递必要的信息
- **文档引用**：让 Agent 自己读取文档，而不是全部传入 context
- **阶段性清理**：完成一个阶段后清理不必要的上下文

### 3.3 审核策略
- **早期严格**：前几集严格审核，建立模式
- **后期放宽**：模式建立后可以适当放宽
- **重点审核**：关键集数（EP-01, EP-20）加强审核

## 4. 常见陷阱与避免方法

### 4.1 记忆污染
**问题**: 手动修改文档后，Recorder 的记录过时

**避免方法**:
```
1. 手动修改后立即更新 script.progress.md
2. 在注意事项中标记"需要人工确认"
3. Aligner 读取时要检查最后更新时间
```

### 4.2 风格漂移
**问题**: 长时间对话后，Agent 忘记创作法则

**避免方法**:
```
1. 每次委派任务时重申核心法则
2. 在 context 中包含关键规则摘要
3. 定期让 Aligner 检查是否符合标准
```

### 4.3 审核僵化
**问题**: Aligner 僵化执行规则，拒绝有创意但不符合规则的剧本

**避免方法**:
```
1. 规则要留有余地（"通常"而不是"必须"）
2. 允许人工覆盖 Aligner 的判断
3. 定期更新审核标准，适应创作需求
```

### 4.4 语义识别失败
**问题**: Recorder 无法识别模糊的决策表达

**避免方法**:
```
1. 使用明确的决策语言（"敲定"、"定了"、"最终版本"）
2. 避免模糊表达（"这个点子很有意思"）
3. 重要决策后立即让 Recorder 记录
```

## 5. 质量提升技巧

### 5.1 前几集建立模式
- **EP-01 严格审核**：通常 3 次迭代，建立冲突模式
- **EP-02 深化关系**：通常 4 次迭代，建立人物关系
- **EP-03 后稳定**：通常 2-3 次迭代，模式已建立

### 5.2 参考模式库
建立常见场景的正确写法库：
```
场景类型 | 错误写法 | 正确写法
---------|---------|---------
开场 | 旁白介绍 | 直接动作（颠簸 + 尖叫）
情感 | "对不起" | "我要你生不如死"
Face-slap | 口头嘲讽 | 泼红酒/推搡
悬念 | "改变一生" | "Montana 见，我的真爱等你"
```

### 5.3 人工介入时机
- **迭代超过 3 次**：立即检查是否是规则问题
- **同一问题反复 FAIL**：修改规则或人工编辑
- **关键集数（EP-20）**：人工重点审核
- **创意与规则冲突**：人工判断是否放宽规则

### 6.1 目录结构
```
project/
├── docs/                  # 文档
│   ├── implementation.md  # 实现指南
│   └── best-practices.md  # 最佳实践
├── prompts/               # Agent 提示词
│   ├── writer.md
│   ├── aligner.md
│   └── recorder.md
├── templates/             # 文档模板
│   ├── outline.md
│   ├── character.md
│   ├── episode-index.md
```

### 6.2 版本控制
- **使用 Git**: 所有文档纳入版本控制
- **阶段性 commit**: 每个阶段完成后 commit
- **清晰的 commit 信息**: "EP-01 通过审核"、"更新人物设定"

### 6.3 备份策略
- **定期备份**: 每天或每个阶段完成后备份
- **多版本保存**: 重要文档保存多个版本
- **云端同步**: 使用云存储防止数据丢失

## 8. 评估与改进

### 8.1 关键指标
- **平均迭代次数**: 应该逐渐降低（3 → 2）
- **审核通过率**: 第一次通过率应该逐渐提高
- **人工介入频率**: 应该逐渐降低
- **创作速度**: 单集创作时间应该逐渐缩短

### 8.2 持续改进
- **定期回顾**: 每周回顾创作质量和效率
- **更新规则**: 根据实际问题调整创作法则
- **优化提示词**: 根据常见问题更新 Agent 提示词
- **积累案例**: 建立成功案例库供参考

### 8.3 反馈循环
```
创作 → 审核 → 记录 → 分析 → 改进 → 创作
                                         ↑
                                        └─┘
```

## 9. 总结

### 核心原则
1. **明确分工**：每个 Agent 专注一个角色
2. **质量门禁**：必须通过审核才能继续
3. **文档驱动**：所有内容持久化存储
4. **人工兜底**：AI 产出 60 分，人工提升到 80 分

### 关键成功因素
1. **严格的审核标准**：Aligner 必须严格把关
2. **清晰的提示词**：每个 Agent 的职责要明确
3. **完善的文档模板**：标准化输出格式
4. **及时的人工介入**：避免无限循环

### 使用建议
- **你是"导演"**：系统提供框架，你负责创意
- **不要过度自动化**：最有价值的部分需要人工
- **平衡质量与成本**：在两者之间找到平衡点
- **持续改进**：根据实际经验不断优化
