# 审查→修改工作流 (Review → Modify Workflow)

> 2026-05-14 基督山伯爵（25集，US市场）验证的审查闭环流程。

## 核心教训

### 1. 子 Agent 审查 = 必超时

| 方案 | 结果 | 根因 |
|------|------|------|
| 子 Agent 读25集剧本做审查 | 600s 超时，输出截断 | 输入 150K+ tokens，分析输出空间 < 5K |
| 子 Agent 读10集关键集 | 仍可能中断 | 审查需要上下文对比，采样不完整 |
| **主 Agent 内联审查（推荐）** | ✅ 完整报告（3文件） | 上下文已加载，无需额外 token |

### 2. 审查报告必须拆分（不合并）

三个视角各写一个文件，不合并到一个大文件。原因：
- 每个报告 ~6-8KB，合并后 ~25KB 难以阅读
- 修改时逐文件引用更清晰
- 综合汇总文件保持精简（~2KB）

### 3. 审查发现的高频问题（US短剧市场）

| 问题 | 频率 | 修复难度 |
|------|------|---------|
| 开场前5秒无冲突 | 高频 | 中（重写开场场景） |
| 时间跳跃无标记 | 中频 | 低（加标题卡） |
| 时代错误（电话/电报） | 中频 | 低（改台词） |
| 逻辑自相矛盾（"三分之一"） | 低频 | 中（重写结尾） |
| 地理跳跃不合理 | 低频 | 高（改场景设计） |
| 拖沓集（纯情感无推进） | 高频 | 高（需加剧情事件） |
| 多人同镜AI翻车 | 极高频 | 中（后期拆分） |

## 审查采样策略

不需要读全部25集。采样策略：

```bash
# 1. 关键集：head -6 + tail -10（获取结构+对白+结尾钩子）
for ep in 01 02 03 04 05 18 20 21 22 23 24 25; do
  head -6 script/EP-$ep.md
  tail -10 script/EP-$ep.md
done

# 2. 道具验证：grep
grep -r "P3\|银项链\|red ruby\|P10" script/ | head -30

# 3. 生图可行性：采样 1-3 集的 Prompts
cat prompts/EP-01.md  # 代表集
cat prompts/EP-25.md   # 高潮集

# 4. 连续性：grep 关键伏笔
grep -r "next episode\|下一集衔接" script/ | head -30
```

## 修改策略

| 类型 | 方法 | 说明 |
|------|------|------|
| 小修（改台词/加标记） | `skill_manage(action='patch')` | 精准替换，保留上下文 |
| 中修（重写场景） | `write_file`（单集） | 重写整集脚本 |
| 大修（改结构） | `write_file` + 更新 continuity.md | 涉及伏笔/衔接 |
| 制作阶段处理 | 记录到 TASK.md | 不改脚本，制作时注意 |

## 审查后必须做的事

1. ✅ 保存审查报告（`REVIEW-*.md`）
2. ✅ 更新 TASK.md（标记修改完成的集）
3. ✅ 分镜/Prompts 保持不变（视听专家的🟢建议是制作阶段处理）
4. ✅ 如果改动了脚本，**分镜/Prompts 需要后续同步修改**（但可以先做后改）
