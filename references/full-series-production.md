## 主 Agent 逐集跑的关键发现

### ✅ 验证了 v2.6 策略
1. **主 Agent 逐集是默认方案** — 20 集一次性完成，质量稳定（平均 90 分）
2. **上下文保持在可管理范围** — 不需要 delegate_task，主 Agent 的上下文足够承载单集创作
3. **连续性追踪有效** — continuity.md 在每集间传递状态，伏笔无遗漏

### ⚠️ 发现的边界条件
1. **长时间 session 的上下文膨胀** — 到 EP-25+ 时，continuity.md + 前序记忆开始占用显著上下文空间。应对：每 5-10 集压缩一次 continuity.md（保留活跃伏笔，归档已回收项）
2. **Prompt 模板重复** — 每集 Prompts 的角色/场景描述高度重复（~2KB/集）。建议：在 Prompts 文件头定义全局变量，单帧 Prompt 用引用代替完整描述（已有 `[ref: C-XX]` 体系，实际执行中可进一步压缩）
3. **审核分数趋同** — 第 2 轮后审核分数稳定在 85-95 区间，说明主 Agent 已经建立了稳定的质量基线。后续集数可以减少审核模板的冗余描述

### 💡 效率提升建议（未来项目）
1. **每集三件套可压缩为 ~3 个 write_file 调用**（而非 5 个）：
   - Script + Storyboard + Prompts 各 1 个
   - Review 内联到 Script 文件末尾（不单独文件）
   - Continuity 每 3-5 集更新一次（不每集更新）
2. **Review 模板可精简**：11 维评分表可压缩为 5 维核心 + 4 维快速检查，从 ~800B 降到 ~400B
3. **Storyboard 和 Prompts 的镜头描述有 70%+ 重叠**：Storyboard 的 Description 列直接成为 Prompt 的核心描述，可考虑在生成时同步产出而非先后依赖

## continuity.md 管理策略（30 集经验）

**早期（EP-01~15）**：详细信息，完整伏笔表 + 角色状态 + 冲突记录
**中期（EP-16~25）**：开始精简，已回收伏笔压缩为一句话
**后期（EP-26~30）**：只保留活跃伏笔 + 当前角色状态 + Last Cliffhanger

**推荐截断规则**：
- EP-15+：已回收伏笔 → 只保留 ID + 一句话
- EP-20+：冲突模式记录 → 只保留最近 3 集
- EP-25+：角色状态 → 只保留还在剧情中的角色
