# 读者评审 v5.0 标准流程（2026-05-14 Carmilla AZ Edit 验证）

> 三位虚拟读者（急躁哥/逻辑控/情感党）对人工修订版剧本的评审流程 + 发现的问题 → Aligner v5.0 升级。

## 评审执行方式

```
1. 用 pymupdf 提取 PDF 剧本全文
2. 按 EPISODE \d+: 切分为单集
3. 为每位读者选取关键集子集（10-12集）
4. 写 review_XX.txt 文件（含选集 + 全集标题列表）
5. delegate_task × 3（每读者一个子 Agent）
6. 汇总评分 + 建议
```

## 子集选择策略

| 读者 | 选择逻辑 | 集数 |
|------|---------|------|
| 急躁哥 | 开场(EP-01~05) + 中段(EP-13~15) + 高潮(EP-31~32) | 10集 |
| 逻辑控 | 关键逻辑节点(EP-01,03,07,11,14,18,24,29,32) | 9集 |
| 情感党 | 情感关键场景(EP-02,06,09,14,19,26,32) | 7集 |

每个评审都附带全集标题列表 + Epilogue 提供全剧上下文。

## 关键教训

1. **读者评审不是可选的** — Carmilla AZ Edit 逻辑控 48 分，如果没做评审，这些毁灭级漏洞会直接进制作流程
2. **Aligner 必须覆盖读者发现的问题** — 每次读者评审后，分析"Aligner 没抓到什么"并升级审核标准
3. **人工修订版也需要评审** — 不是只有 AI 生成的才需要审核，人工修改可能引入新的逻辑漏洞
4. **评审结果应该驱动 Skill 更新** — 不只是"提意见"，更是"升级系统"
